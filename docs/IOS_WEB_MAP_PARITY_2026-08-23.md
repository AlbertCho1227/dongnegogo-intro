# iOS ↔ 웹 지도 기능 비교 요약

검증일: 2026-08-23
기준: iOS 프로젝트 52개 Swift 파일(약 47,847줄) 읽기 전용 분석, iPhone 17 Pro / iOS 26.5 시뮬레이터 주요 시나리오 확인, 웹 데스크톱·360×780·390×844·430×932 반응형 브라우저 확인

## 결론

- 모바일 지도 GUI·탭·시트 구현률: **약 94%** (이전 PC 축소형 레이아웃)
- 지도 탐색 핵심 흐름 구현률: **약 93%** (이전 82%)
- 경로·목적지 주변 가게 구현률: **약 92%** (이전 62%)
- 계정·알림·가족을 포함한 iOS 전체 서비스 구현률: **약 85%** (이전 66%)
- 이번 수치는 2026-08-23 공개 배포 승인본의 구현·검증 기준이다.
- 운영 Supabase 데이터·스키마·Auth 설정과 iOS 소스는 변경하지 않았다. 웹 로그인 후 발생하는 찜·알림·가족·동의 기록만 기존 사용자 소유 RLS 계약을 사용하도록 구현했다.

## 실제 확인한 반응 시나리오

1. 운영 경로 계약을 직접 호출해 도보 137m/8,384m, 대중교통 33분/13,633m, 자동차 15분/8,682m의 실제 비추정 결과와 지도 경로 좌표를 확인했다.
2. 웹에서 상세 화면의 Kakao Roadview가 실제 도로 장면을 표시하는 것을 확인했다.
3. 목적지 100m 주변 가게 34곳을 불러오고 분류 마커·선택 강조·실제 도보 1분/40m 경로가 표시되는 것을 확인했다.
4. 다른 목적지의 300m 반경에서 15곳을 표시하고 선택 가게까지 실제 도보 7분/330m가 표시되는 것을 확인했다.
5. iOS 시뮬레이터에서 지도 전체 화면·하단 5개 탭·찾기 자동 포커스·오픈런·같은 장소 1/N 시트·상세·주변 목록·로그인 시트·내정보 카드 순서를 읽기 전용으로 대조했다.
6. 웹에서 단일 로그인 CTA, 법적 동의 안내, 약관 링크, Kakao/Apple/Google 선택 화면을 브라우저로 확인했다. 실제 OAuth 이동은 운영 리다이렉트 미승인 상태라 실행하지 않았다.
7. 360×780·390×844·430×932 화면에서 지도 폭과 화면 폭이 일치하고 가로 넘침이 없으며, 지도 탭에서 PC 목록이 숨겨지고 하단 메뉴가 화면 하단에 고정되는 것을 확인했다.
8. 390×844 화면에서 찾기·오픈런·내정보가 전체 화면으로 열리고, 마커 선택은 약 440px 바텀시트, 주변 목록·프로그램 상세·달력은 전체 시트로 열리는 것을 확인했다.
9. 1440×900 화면에서 왼쪽 메뉴 88px, 프로그램 패널 430px, 오른쪽 지도 922px의 기존 PC 분할 구성이 유지되는 것을 확인했다.
10. 프로덕션 빌드와 자동 테스트 59개(51 통과, 환경 의존 8 건너뜀), 정적 검사 0 오류를 확인했다.

## 100%에 남은 항목과 이유

1. **웹 로그인 실사용:** Supabase Auth 리다이렉트 허용 목록에 운영 도메인을 추가해야 한다. 코드와 UI는 준비됐지만 원격 Auth 설정 변경은 별도 승인이 필요하다.
2. **브라우저가 닫힌 뒤 알림:** iOS 로컬 알림과 달리 Web Push 서비스 워커·구독 저장 테이블·서버 발송 작업이 필요하다. 현재는 페이지가 열린 동안의 알림과 계정 일정 저장까지만 동작한다.
3. **여러 알림 시간:** 운영 DB는 현재 프로그램당 `scheduled_at` 한 개만 지원한다. iOS형 복수 시간은 준비된 별도 마이그레이션을 승인·배포해야 한다.
4. **리뷰·사진·계정 삭제 실행:** 사용자 쓰기 RLS, 저장소 정책, 삭제용 서버 함수와 악용 방지 정책을 함께 확정해야 한다.
5. **플랫폼 고유 차이:** iOS 네이티브 위치·알림·Apple 로그인과 웹 브라우저 권한 UX는 완전히 같은 화면이 될 수 없으므로, 결과와 상태 전이는 같게 맞추되 권한 안내는 플랫폼 규칙을 따라야 한다.

현재 웹 버전 공개 배포는 승인되었다. **Supabase Auth 리다이렉트 등록**은 여전히 별도 승인 범위이며, Web Push·복수 알림·리뷰 쓰기도 별도 보안 검토 후 후속 승인 범위로 분리한다.
